# Packaging

Everything here repackages a release, it does not build one. The binaries
come from the GitHub release that `dist` creates (`release.yml`): static musl
builds for Linux, so every channel below ships the same bytes as the tarball
and the installer script. The Debian packages are the exception, compiled per
architecture by `cargo deb` in `packages.yml`.

| Channel | Source | Published by | Users run |
|---|---|---|---|
| apt repository, `octomon.dev/apt` | `cargo deb` (metadata in `Cargo.toml`) | `.github/workflows/packages.yml`, `build-apt-repo.sh` | `apt install octomon` |
| rpm repository, `octomon.dev/rpm` | [`rpm/octomon.spec`](rpm/octomon.spec) over the release tarballs | `packages.yml`, `build-rpm-repo.sh` | `dnf install octomon`, `zypper install octomon` |
| AUR `octomon-bin` | [`aur/PKGBUILD.in`](aur/PKGBUILD.in), rendered by [`aur/render.sh`](aur/render.sh) | `.github/workflows/aur.yml` | `paru -S octomon-bin` |
| Nix flake | [`nix/package.nix`](nix/package.nix), wired up by `/flake.nix` | the repository itself | `nix run github:securitypedant/octomon` |
| winget `SimonThorpe.Octomon` | [`winget/`](winget/) | `.github/workflows/winget.yml` | `winget install SimonThorpe.Octomon` |
| Homebrew tap | `octomon.rb`, generated by `dist` | `release.yml` | `brew install octomon` |

Both repositories are signed with the same key (`APT_SIGNING_KEY` in CI; the
public half is served beside each repo as `octomon.gpg`), rebuilt from scratch
on each release and hold the current version only; older packages stay on the
GitHub releases.

## Trying a change locally

The rpm and AUR paths run in containers against a published release, no CI
needed:

```sh
# rpm: build both arches, sign with a throwaway key, install from the tree
rpmbuild -bb --target x86_64 --define "version 0.12.1" --define "_sourcedir $PWD" packaging/rpm/octomon.spec
.github/scripts/build-rpm-repo.sh rpms repo <key-id>

# AUR: render for a release, then makepkg in an Arch container
packaging/aur/render.sh 0.12.1 out && cat out/PKGBUILD

# Nix: build from the working tree
nix build . && ./result/bin/octomon --version
```

## Sending the Nix package upstream

`nix/package.nix` is already in nixpkgs' `callPackage` shape. For a
`pkgs/by-name/oc/octomon/package.nix` PR: replace `src` with
`fetchFromGitHub` at the release tag, `cargoLock` with `cargoHash`, and fill
in `maintainers`.
